# 비즈업 정산 서비스 이전 구현 명세

> 문서 상태: 현재 구현 기준 재구현 명세  
> 기준 계산 엔진: `2026.08.09.1`  
> 기준 입력: 기존 `.xlsx` 월별 정산 파일  
> 목적: 기존 소스 코드 없이도 동일한 입력에 대해 동일한 분석 결과, 정산서 계산 결과, 저장 및 PDF 출력 동작을 구현한다.

## 1. 서비스 범위

이 서비스는 하나 이상의 월별 정산 엑셀을 입력받아 다음 기능을 수행한다.

1. 각 파일에서 강사명을 자동 수집한다.
2. 강사별·월별 토스 매출, PG 수수료, 현금 매출, 부가서비스 이용료를 집계한다.
3. 아래 계산식으로 강사별 월 정산금과 최종 정산금을 계산한다.
4. 각 월의 `비즈업_요약` 시트에 있는 8개 금액과 계산 결과를 대조한다.
5. 여러 월을 시간순으로 정렬하고 강사별 누적 합계를 만든다.
6. 강사별 원본 거래 내역과 월별 계산 결과를 PDF 정산표로 출력한다.
7. 강사별 최종 정산금을 A값으로 가져와 B~E 비용, 사업자/개인 처리, 참여 강사 배분을 반영한 최종 정산서를 작성한다.
8. 원본 파일, 분석 결과, 정산서 입력값을 로컬 SQLite 작업 단위로 저장하고 복원한다.

계산과 정산서 작성은 별도 단계이다.

- 1차 엑셀 분석: 월별 매출 자료로 `finalSettlement`를 계산한다.
- 2차 정산서 작성: 여러 월의 `finalSettlement` 합계가 정산서의 A가 되며, 수동 입력한 B~E 비용을 추가 반영한다.

## 2. 핵심 호환성 원칙

새 서비스는 다음 원칙을 반드시 지켜야 기존 결과와 일치한다.

- 열 제목을 찾아 동적으로 매핑하지 않고, 아래에 정의한 고정 열 위치를 사용한다.
- 강사명은 정규화한 뒤 완전 일치로 연결한다.
- 취소 행을 제외하지 않는다. 음수 금액을 포함해 모든 일치 행을 그대로 합산한다.
- 모든 원본 금액 셀을 먼저 원 단위로 반올림한 뒤 합산한다.
- 계산 결과도 명시된 각 중간 단계마다 원 단위로 반올림한다.
- 시스템노바 수수료 3.3%는 강사별·월별 `settlementBase`에 각각 적용하고 반올림한 뒤 누적한다.
- 여러 월의 전체 금액에 3.3%를 한 번만 적용하면 기존 서비스와 몇 원 차이가 날 수 있으므로 금지한다.
- 현금매출 시트가 없어도 파일은 정상 처리하며 현금 관련 값은 0이다.
- 월별 계산을 완료한 뒤 월 결과를 더한다. 원본 행을 여러 파일에서 먼저 합쳐 한 번에 계산하지 않는다.

## 3. 입력 파일 계약

### 3.1 파일 단위 제약

- 확장자: `.xlsx`만 허용한다. 대소문자는 구분하지 않는다.
- 파일당 최대 크기: 25 MiB (`25 × 1024 × 1024` 바이트).
- 여러 파일을 한 번에 선택하거나 순차적으로 추가할 수 있다.
- 같은 작업 안에서 `(파일명, 파일 크기, lastModified)`가 모두 같은 파일은 중복으로 거부한다.
- 파일 추가/삭제 후 기존 분석은 `stale` 상태로 간주하며 다시 분석해야 한다.

### 3.2 시트명

| 시트명 | 필수 여부 | 용도 |
|---|---:|---|
| `비즈업_토스` | 필수 | 토스 결제·취소액 및 PG 수수료 |
| `비즈업_무통장` | 선택 | 현금 결제액 및 취소액 |
| `비즈업_부가서비스` | 필수 | 강사별 부가서비스 이용료 |
| `비즈업_요약` | 필수 | 월 계산 결과 검증 및 정산 월 탐지 |

시트명 비교 규칙은 다음과 같다.

1. 실제 시트명에 Unicode NFKC 정규화를 적용한다.
2. 시트명 앞뒤 공백을 제거한다.
3. 위 표의 이름과 완전히 같은지 비교한다.

대소문자 변환이나 내부 공백 제거는 하지 않는다.

### 3.3 열 매핑

아래 열 번호는 엑셀 화면 기준 1부터 시작한다.

#### `비즈업_토스`

| 열 | 일반적인 제목 | 계산/출력 용도 |
|---:|---|---|
| B(2) | 매출일 | PDF 거래일 |
| F(6) | 결제수단 | PDF 상세 |
| G(7) | 결제상태 | PDF 상세 |
| H(8) | 결제기관 | PDF 상세 |
| I(9) | 구매자명 | PDF 상세 |
| K(11) | 결제·취소액 (A) | `tossSales` 합산 |
| L(12) | PG수수료 (B) | `pgFee` 합산 |
| M(13) | 공급가액 | PDF 상세만 사용 |
| N(14) | 부가세 | PDF 상세만 사용 |
| P(16) | 카드 매입상태 | PDF 상세 |
| T(20) | 강사명 | 강사 수집 및 행 매칭 |

#### `비즈업_무통장`

| 열 | 일반적인 제목 | 계산/출력 용도 |
|---:|---|---|
| B(2) | 결제일시 | PDF 거래일 |
| C(3) | 구매자명 | PDF 상세 |
| D(4) | 구매자이메일 | PDF 상세 |
| E(5) | 구매자전화번호 | PDF 상세 |
| F(6) | 결제액 | `cashPayments` 합산 |
| G(7) | 취소액 | `cashCancellations` 합산 |
| H(8) | 강의명 | PDF 상세 |
| I(9) | 강사명 | 강사 수집 및 행 매칭 |

취소액은 파일에 기록된 부호 그대로 더한다. 일반적으로 취소는 음수로 입력되어야 하며, 서비스가 양수를 자동으로 음수로 바꾸지 않는다.

#### `비즈업_부가서비스`

| 열 | 일반적인 제목 | 계산/출력 용도 |
|---:|---|---|
| B(2) | 강사명 | 강사 수집 및 행 매칭 |
| C(3) | 이용서비스 명 | PDF 상세 |
| D(4) | 이용날짜 | PDF 상세 |
| E(5) | 기타 비용 | PDF 상세만 사용 |
| F(6) | 총계 | `additionalServiceFee` 합산 |
| G(7) | 비고 | PDF 상세 |

중요: 계산에는 E열이 아니라 F열만 사용한다.

`강사명` 헤더가 B열에 있으면 그 다음 행부터 데이터 행으로 판단한다. 이후 값이 하나라도 있는 행의 B열이 비어 있으면 파일 전체를 오류 처리하고 실제 엑셀 행 번호를 표시한다. 헤더를 찾지 못하면 첫 행부터 같은 검사를 한다.

#### `비즈업_요약`

고정 열 위치를 사용하지 않는다. 각 행에서 아래 레이블과 정확히 일치하는 셀을 찾고, 같은 행에서 그 셀 오른쪽에 있는 첫 번째 유효 숫자를 값으로 사용한다.

1. `총매출`
2. `토스매출액`
3. `PG수수료`
4. `현금매출액`
5. `정산기준액`
6. `시스템노바 수수료`
7. `부가서비스 이용료`
8. `비즈업클래스 정산금`

따라서 기존 파일처럼 레이블이 B열이고 금액이 D열인 구조와, 레이블이 C열이고 금액이 E열인 구조를 모두 처리해야 한다.

## 4. 값 정규화

### 4.1 강사명 정규화

모든 시트의 강사명과 검색 대상 강사명에 아래 변환을 같은 순서로 적용한다.

```text
normalizeName(value):
  1. null, undefined, 날짜 객체이면 빈 문자열
  2. 문자열로 변환
  3. Unicode NFKC 정규화
  4. U+200B~U+200D, U+2060, U+FEFF 제거
  5. 앞뒤 공백 제거
  6. 연속 공백 문자를 일반 공백 1개로 축약
```

정규화 후 문자열을 완전 일치로 비교한다.

- `김\u200B해준`과 `김해준`은 같다.
- `엘플랑x두뜬`과 `엘플랑,두뜬`은 다르다.
- 영문 대소문자는 변환하지 않는다.
- 특수문자, 쉼표, `x` 등을 임의로 통일하지 않는다.

### 4.2 강사 목록 수집

강사명은 다음 세 위치의 합집합이다.

- 토스 T열
- 무통장 I열
- 부가서비스 B열

빈 값과 정확히 `강사명`인 헤더 값은 제외한다. 중복을 제거하고 한국어 로케일 기준 오름차순으로 정렬한다. 특정 시트에만 존재하는 강사도 결과에 포함한다.

### 4.3 일반 금액 파싱

```text
parseAmount(value):
  숫자형이고 유한수이면 그대로 반환
  숫자형이지만 NaN/Infinity이면 0
  문자열이 아니면 0
  빈 문자열이면 0
  문자열에서 ₩, '원', 쉼표, 모든 공백, 괄호를 제거
  제거한 결과를 숫자로 변환할 수 없으면 0
  원문 전체가 괄호로 감싸져 있으면 음수 절댓값으로 반환
```

예:

| 입력 | 결과 |
|---|---:|
| `1,234원` | 1234 |
| `₩ 1,234` | 1234 |
| `(1,234)` | -1234 |
| `-1,234` | -1234 |
| 빈 값 또는 숫자가 아닌 문자열 | 0 |

### 4.4 원 단위 반올림

모든 원 단위 반올림은 양수와 음수의 정확한 절반을 0에서 멀어지는 방향으로 처리한다.

```text
roundWon(x):
  x < 0 이면 -round(-x)
  그 외에는 round(x)
```

예: `100.5 → 101`, `-20.5 → -21`, `100.49 → 100`.

JavaScript 이외 언어로 옮길 때 해당 언어의 기본 `round`가 bankers rounding인지 반드시 확인한다. bankers rounding이면 이 결과와 일치하지 않는다.

## 5. 1차 엑셀 정산 계산

### 5.1 강사별·월별 원본 합산

대상 강사와 정규화된 강사명이 같은 모든 행을 사용한다.

```text
tossSales          = Σ roundWon(토스 K열)
pgFee              = Σ roundWon(토스 L열)
cashPayments       = Σ roundWon(무통장 F열)
cashCancellations  = Σ roundWon(무통장 G열)
additionalServiceFee = roundWon(Σ roundWon(부가서비스 F열))
```

각 시트별 매칭 행 수도 함께 저장한다.

- `tossMatchCount`
- `cashMatchCount`
- `serviceMatchCount`

헤더 행은 강사명이 `강사명`이므로 실제 강사와 일치하지 않아 자연스럽게 제외된다. 결제상태에 따른 별도 필터는 없다. 완료, 취소, 부분취소를 포함한 모든 행의 금액 부호를 그대로 합산한다.

### 5.2 계산식과 정확한 순서

강사 1명, 월 1개에 대해 아래 순서를 그대로 구현한다.

```text
cashSales         = roundWon(cashPayments + cashCancellations)
totalSales        = roundWon(tossSales + cashSales)
settlementBase    = roundWon(totalSales - pgFee)
systemNovaFee     = roundWon(settlementBase × 0.033)
novaSettlementBase = roundWon(settlementBase - cashSales)
settlementAmount  = roundWon(novaSettlementBase - systemNovaFee - additionalServiceFee)
finalSettlement   = roundWon(settlementAmount + cashSales)
```

동일한 식을 펼치면 다음과 같지만, 반올림 호환성을 위해 위 중간 단계 순서를 유지해야 한다.

```text
settlementAmount = settlementBase - cashSales - systemNovaFee - additionalServiceFee
finalSettlement  = settlementAmount + cashSales
```

의미:

- `settlementAmount`는 플랫폼을 통해 실제로 지급할 금액이므로 이미 입금된 현금매출을 제외한다.
- `finalSettlement`는 현금매출을 다시 더한 강사의 전체 정산 재원이며, 2차 정산서의 A 산출에 사용한다.
- 현금매출만 있는 강사도 `settlementBase`에 대해 시스템노바 수수료가 계산된다. 따라서 `settlementAmount`가 수수료만큼 음수가 되고 `finalSettlement`는 현금매출에서 그 수수료를 뺀 값이 된다.

### 5.3 계산 의사코드

```text
for each workbook:
  instructors = union(
    normalized nonblank toss.T,
    normalized nonblank cash.I,
    normalized nonblank service.B
  )

  for each instructor:
    tossRows    = rows where normalize(row.T) == instructor
    cashRows    = rows where normalize(row.I) == instructor
    serviceRows = rows where normalize(row.B) == instructor

    tossSales         = sum(roundWon(parseAmount(row.K)))
    pgFee             = sum(roundWon(parseAmount(row.L)))
    cashPayments      = sum(roundWon(parseAmount(row.F)))
    cashCancellations = sum(roundWon(parseAmount(row.G)))
    serviceFee        = sum(roundWon(parseAmount(row.F)))

    calculate intermediate values in section 5.2
```

### 5.4 검증용 예시

원본 셀이 다음과 같다고 가정한다.

- 토스 결제액: `100.49`, `100.5`, `-20.5`
- 토스 PG 수수료: `3.5`, `0`, `0`
- 현금 결제액: `50.5`
- 현금 취소액: `-10.5`
- 부가서비스 총계: `5.5`

셀별 반올림 결과와 최종 결과:

```text
tossSales = 100 + 101 - 21 = 180
pgFee = 4
cashPayments = 51
cashCancellations = -11
cashSales = 40
totalSales = 220
settlementBase = 216
systemNovaFee = roundWon(216 × 0.033) = 7
additionalServiceFee = 6
settlementAmount = 216 - 40 - 7 - 6 = 163
finalSettlement = 163 + 40 = 203
```

이 예시는 이식 구현의 필수 골든 테스트로 사용한다.

## 6. 월 판별과 여러 파일 통합

### 6.1 요약 제목

`비즈업_요약`의 모든 셀을 행 우선으로 탐색하여 정규화된 문자열에 `비즈업클래스`와 `매출 요약`이 모두 포함된 첫 셀을 제목으로 사용한다. 찾지 못하면 `비즈업클래스 매출 요약`을 기본값으로 쓴다.

### 6.2 월 판별 우선순위

월과 연도는 파일명 및 요약 제목에서 다음 형식을 인식한다.

- 파일명: `26.05`, `2026.06`, `26-07`, `2026_08`
- 요약 제목: `5월`, `2026년 6월`, `26년 7월`

결정 규칙:

1. 월은 요약 제목에서 찾은 값을 우선하고, 없으면 파일명 값을 사용한다.
2. 연도는 요약 제목에서 찾은 값을 우선하고, 없으면 파일명 값을 사용한다.
3. 두 자리 연도는 2000을 더한다. 예: `26 → 2026`.
4. 월이 있으면 표시값은 연도 유무에 따라 `2026년 5월` 또는 `5월`이다.
5. 월을 찾지 못하면 확장자를 뺀 파일명을 표시값으로 쓰고 정렬상 맨 뒤에 둔다.
6. 정렬 키가 같으면 사용자가 입력한 파일 순서를 유지한다.

### 6.3 강사별 누적

모든 월에 등장한 강사명의 합집합을 만든 뒤 한국어 오름차순으로 정렬한다. 어떤 월에 해당 강사가 없으면 그 월의 모든 금액과 매칭 건수가 0인 빈 결과를 삽입한다.

누적 결과는 월별로 이미 계산·반올림된 아래 필드를 단순 합산한다.

- `totalSales`, `tossSales`, `pgFee`
- `cashPayments`, `cashCancellations`, `cashSales`
- `settlementBase`, `systemNovaFee`, `additionalServiceFee`
- `settlementAmount`, `finalSettlement`
- 세 종류의 매칭 건수

전체 강사 합계도 강사별 결과를 합산한다. 단, 전체 `totalSales`는 최종적으로 `전체 tossSales + 전체 cashSales`로 계산한다.

## 7. 요약 시트 대조

각 파일마다 8개 항목을 독립적으로 비교한다.

### 7.1 요약 금액 파싱

- 숫자형 유한수는 허용한다.
- 문자열에서는 `₩`, `원`, 쉼표, 공백을 제거한다.
- 제거 후 `-12`, `12.3` 같은 일반 10진 숫자 형식만 허용한다.
- 괄호 음수는 요약 값 파서에서 지원하지 않는다.
- 찾은 요약 값도 비교 전에 `roundWon`한다.

### 7.2 비교 규칙

```text
difference = calculatedValue - summaryValue
matches = summaryValue가 존재하고 abs(difference) < 0.01
```

모든 값이 원 단위 정수이므로 실질적으로 차액이 0일 때만 일치한다. 레이블 또는 숫자가 없으면 `summaryValue`, `difference`는 `null`이고 불일치이다.

`비즈업클래스 정산금`은 `finalSettlement`가 아니라 현금매출을 다시 더하기 전의 `settlementAmount`와 비교한다.

파일별 `allMatched`는 8개가 모두 일치할 때만 참이다. 전체 `allMatched`는 비교 항목 수가 1개 이상이고 모든 월의 모든 항목이 일치할 때만 참이다.

## 9. 강사별 정산표 PDF용 원본 상세

강사 카드의 `정산표 PDF`는 계산 결과뿐 아니라 해당 강사와 일치하는 원본 행을 월순으로 출력한다. 원본 행 순서는 엑셀에 기록된 순서를 유지한다.

금액은 모두 `parseAmount` 후 `roundWon`한다. 날짜 셀이 날짜 객체이면 UTC 필드로 `YYYY-MM-DD`를 만들고 시·분이 00:00이 아니면 `YYYY-MM-DD HH:mm`으로 출력한다. 문자열 날짜는 정규화 후 그대로 출력한다.

PDF 파일명:

```text
[강사명]_정산표.pdf
```

Windows 파일명 금지문자 `\ / : * ? " < > |`는 `_`로 바꾼다.

출력 데이터는 3.3절의 PDF 상세 열 매핑을 따른다. 월별 계산 요약과 전체 누적 합계도 포함한다.

## 10. 2차 정산서 작성

### 10.1 A값

정산서의 A는 선택한 강사의 모든 월 `finalSettlement` 합계이다.

```text
A = aggregatedInstructorResult.finalSettlement
  = Σ 각 월 finalSettlement
```

월별 원본 파일명, 기간, 월 `finalSettlement`를 함께 표시한다.

### 10.2 B~E 비용 의미

| 코드 | 기본 명칭 | 차감 시점/대상 |
|---|---|---|
| B | 자체비용 | 50:50 분배 후 플랫폼 몫에서 차감 |
| C | 광고마케팅비용 | 50:50 분배 전에 A에서 차감하는 공동비용 |
| D | 부대비용 | 50:50 분배 전에 A에서 차감하는 공동비용 |
| E | 강사님비용정산 | 50:50 분배 후 강사 몫에서 차감 |

비용 항목은 추가/삭제할 수 있다. 각 비용 항목의 금액을 먼저 `roundWon`하고 그룹별, 구분별로 합산한다.

```text
groupTotal   = roundWon(Σ roundWon(item.amount))
sectionTotal = roundWon(Σ groupTotal)
```

### 10.3 정산서 계산식

```text
A = roundWon(엑셀 누적 finalSettlement)
B, C, D, E = 각 구분 합계

F = roundWon(A - C - D)                 // 최종정산, 분배 가능 금액
G = roundWon(F × 0.50)                  // 강사 몫
H = roundWon(F × 0.50)                  // 플랫폼 몫
I = roundWon(G - E)                     // 강사 공급가액/원천징수 기준액

사업자 처리:
  VAT = roundWon(I × 0.10)
  J_business = roundWon(I + VAT)

개인 처리:
  withholding = roundWon(I × 0.033)
  J_individual = roundWon(I - withholding)

K = roundWon(H - B)                     // 플랫폼 비용 정산 후 금액
```

한 문서에서는 사업자 처리 또는 개인 처리 중 하나만 선택한다. 화면과 PDF에는 선택한 J만 최종 지급액으로 사용한다. 기본 선택은 사업자 처리이다.

중요한 구현 해석:

- B는 강사 지급액 J에 영향을 주지 않고 K에만 영향을 준다.
- C와 D는 분배 전에 차감되므로 각 비용의 50%씩 강사와 플랫폼에 실질 반영된다.
- E는 강사 몫 G에서 전액 차감한 후 VAT 또는 원천징수를 계산한다.
- 사업자 VAT와 개인 원천징수는 모두 E 차감 후 I를 기준으로 한다.
- 음수 중간값도 제한하지 않고 동일한 반올림 규칙으로 계산한다.

### 10.4 정산서 계산 검증 예시

```text
A = 122,253,151
B = 10,749,500
C = 38,381,223
D = 2,669,400
E = 4,373,000

F = 81,202,528
G = 40,601,264
H = 40,601,264
I = 36,228,264
VAT = 3,622,826
J_business = 39,851,090
withholding = 1,195,533
J_individual = 35,032,731
K = 29,851,764
```

이 값도 필수 골든 테스트로 사용한다.

### 10.5 정산서 발행 정보

저장해야 할 입력값:

- 발행일: 기본값은 사용자 로컬 날짜 `YYYY-MM-DD`
- 처리 방식: `business` 또는 `individual`
- 수신 회사/사업자명
- 강의명
- 닉네임
- 기수
- 담당자명
- 전화번호
- 이메일
- B~E의 그룹, 상세 항목명, 금액, 비고
- 참여 강사명과 분배율

발행자는 `주식회사 비즈업클래스`로 고정한다.

문서 제목과 PDF 파일명은 다음과 같다.

```text
[강의명]-[기수] 최종 정산서
[강의명]-[기수] 최종 정산서.pdf
```

PDF 생성 전 수신 회사/사업자명, 강의명, 기수는 필수이다.

## 11. 엑셀 비용 표 붙여넣기

정산서 화면은 엑셀에서 복사한 탭 구분 텍스트를 B~E 상세 항목에 반영한다.

예상 열 구조:

```text
1열: 구분명
2열: 구분 코드 또는 그룹명
3열: 상세 항목명
4열: 금액
5열 이후: 비고
```

파싱 규칙:

1. 줄바꿈을 `\n`으로 통일하고 행 단위로 처리한다.
2. 각 행을 탭으로 나누고 최소 5칸이 되도록 빈 칸을 채운다.
3. 1열이 비어 있지 않고 2열이 `(B)`, `B`, `(C)` 등 B~E 코드이면 새 구분 행이다.
4. 구분 안에서 2열에 값이 있고 3열이 비어 있으면 그룹 행이다.
5. 3열에 값이 있으면 상세 항목 행이다.
6. 상세 항목명이 `총합`을 포함하거나 `합계`로 끝나면 중복 합산 방지를 위해 제외한다.
7. 그룹명과 항목명은 NFKC, 소문자화 후 영문/숫자/한글 이외 문자를 제거하여 우선 매칭한다.
8. 이름이 맞지 않으면 아직 사용하지 않은 같은 순번 이후 그룹 또는 첫 미사용 항목에 순서대로 대응한다.
9. 기존 항목보다 붙여넣은 상세 행이 많으면 새 항목을 만든다.
10. 단일 항목 그룹에 상세 행이 없고 그룹 합계만 있으면 그 합계를 단일 항목에 적용한다.
11. 표의 그룹/구분 합계와 상세 합계가 다르면 경고하지만 적용 자체는 유지한다.

붙여넣기 금액은 일반 금액과 유사하게 괄호 음수, `원`, `₩`, 쉼표, 공백을 처리하고 즉시 원 단위 반올림한다.

## 12. 참여 강사 배분

참여 강사는 선택 사항이다. 이름이 비어 있는 행은 계산과 PDF에서 제외한다. 참여 강사가 없으면 PDF에 이 구역을 표시하지 않는다.

배분 기준 금액:

```text
selectedPayment = paymentType == business ? J_business : J_individual
```

각 참여 강사:

```text
sharePercent = 유한수이면 max(0, 입력값), 아니면 0
amount = roundWon(selectedPayment × sharePercent / 100)
```

전체:

```text
totalPercent = 모든 유효 참여 강사의 sharePercent 합을 소수 셋째 자리로 반올림
distributedAmount = roundWon(각 amount 합계)
remainingAmount = roundWon(selectedPayment - distributedAmount)
```

`totalPercent`가 부동소수 오차 범위 `0.0001` 이내에서 100이면, 개별 반올림으로 생긴 차액을 마지막 유효 참여 강사의 지급액에 더해 총액을 정확히 맞춘다.

예:

```text
selectedPayment = 100,001
분배율 = 33.3%, 33.3%, 33.4%
개별 결과 = 33,300 / 33,300 / 33,401
합계 = 100,001, 잔액 = 0
```

현재 화면에서는 문서 전체 처리 방식을 하나만 선택하며 모든 참여 강사에게 같은 처리 방식과 같은 기준 지급액을 적용한다.

## 13. 정산 정보 JSON 파일

강사별 정산서 작성 내용을 별도 보조 파일로 내보낼 수 있다.

- 파일명: `[강사명]_정산정보.bizup.json`
- 인코딩: UTF-8 JSON
- 최대 불러오기 크기: 5 MiB
- 현재 종류: `bizup-settlement-statement`
- 현재 버전: `8`

현재 출력 구조:

```json
{
  "kind": "bizup-settlement-statement",
  "version": 8,
  "savedAt": "ISO-8601 시각",
  "issuer": "주식회사 비즈업클래스",
  "result": { "...": "강사별 누적 분석 결과" },
  "draft": { "...": "정산서 입력 정보" }
}
```

기존 서비스는 버전 1~8을 읽고 현재 구조로 마이그레이션하지만, 새 서비스가 과거에 저장한 JSON까지 받아야 한다면 동일한 하위 호환 마이그레이션이 필요하다. 입력 엑셀만 호환 대상이라면 버전 8 출력/입력만 구현해도 핵심 계산 이식에는 영향이 없다.

## 14. 작업 저장 및 복원

현재 서비스는 기본적으로 `data/bizup-settlement.sqlite`를 사용한다. 다른 저장소를 쓰더라도 아래 논리 모델과 상태 전이를 유지하면 된다.

### 14.1 작업 단위

작업은 다음을 하나로 묶는다.

- 작업 이름과 상태
- 업로드한 원본 `.xlsx` 바이너리와 메타데이터
- 파싱된 워크북 JSON
- 분석 결과 JSON
- 강사별 정산서 초안 및 계산 결과

작업 상태:

| 상태 | 의미 |
|---|---|
| `draft` | 새 작업, 아직 분석 없음 |
| `stale` | 파일이 추가/삭제되어 기존 분석이 현재 입력과 불일치 |
| `analyzed` | 현재 입력 파일들로 분석 완료 |

### 14.2 무결성과 동시 편집

- 원본 파일 콘텐츠의 SHA-256을 저장한다.
- 분석 저장 시 현재 파일 ID와 콘텐츠 해시를 순서대로 결합해 SHA-256 입력 지문을 만든다.
- 계산 엔진 버전이 저장 결과의 버전과 다르면 기존 분석을 표시하지 않고 재분석을 요구한다.
- 작업 이름과 강사별 정산서에는 정수 `revision`을 사용한 낙관적 잠금을 적용한다.
- revision이 다르면 HTTP 409에 해당하는 충돌로 처리하고, 사용자가 최신값 다시 불러오기 또는 강제 저장을 선택할 수 있게 한다.
- 정산서 입력은 마지막 변경 후 500ms debounce로 자동 저장한다.
- 작업 삭제 시 원본 파일, 분석, 정산서 초안을 함께 삭제한다.

### 14.3 권장 논리 테이블

```text
workspaces
  id, name, status, active_analysis_id, period_labels,
  file_count, instructor_count, revision, timestamps

input_files
  id, workspace_id, name, size, mime_type, last_modified,
  content_hash, file_blob, display_order, created_at

analyses
  id, workspace_id, engine_version, input_fingerprint,
  input_file_ids, parsed_workbooks, result, data_version, created_at

statement_drafts
  id, workspace_id, instructor, instructor_key,
  draft, calculation, draft_version, engine_version, revision, updated_at
```

강사 초안의 키는 정규화한 강사명을 한국어 로케일 소문자로 바꾼 값을 사용한다.

## 15. 사용자 동작 흐름

### 15.1 분석

1. 서비스 접속 시 저장소 상태를 확인한다.
2. 저장된 작업이 있으면 가장 최근 작업을 연다.
3. 사용자가 새 작업을 만들거나 기존 작업을 선택한다.
4. 월별 `.xlsx` 파일을 추가한다. 원본은 즉시 작업 저장소에 저장한다.
5. `분석하기`를 누르면 저장된 원본을 다시 읽어 모든 파일을 파싱한다.
6. 어느 한 파일이라도 유효하지 않으면 파일명을 포함한 오류를 보여주고 분석 저장을 중단한다.
7. 모든 파일이 성공하면 월별 분석, 강사별 누적, 요약 대조를 저장하고 표시한다.

### 15.2 결과 화면

- 전체 파일 수, 강사 수, 전체 `finalSettlement`를 표시한다.
- 월별로 요약 시트의 8개 항목, 계산값, 요약값, 차액을 표시한다.
- 강사별로 전체 기간 최종 정산금, 월별 최종 정산금, 월별 7개 주요 지표와 누적 지표를 표시한다.
- 금액 복사는 통화 기호와 쉼표 없이 반올림된 정수 문자열만 복사한다. 음수 기호는 유지한다.
- 강사별 `정산표 PDF`와 `정산서 작성` 진입을 제공한다.

### 15.3 정산서

1. 강사 카드에서 정산서 작성을 연다.
2. 기존 초안이 없으면 기본 템플릿을 생성한다.
3. 발행 정보, 처리 방식, B~E 비용, 참여 강사를 입력한다.
4. 변경할 때마다 계산 결과를 즉시 갱신하고 500ms 후 저장한다.
5. 보조 JSON 저장 또는 PDF 출력을 제공한다.
6. PDF는 선택한 사업자/개인 지급 방식 하나만 반영한다.

## 16. 오류 처리 계약

최소한 다음 오류를 구분해 사용자에게 알려야 한다.

| 조건 | 처리 |
|---|---|
| `.xlsx`가 아님 | 파일 거부 |
| 파일이 25 MiB 초과 | 파일 거부 |
| 토스/부가서비스/요약 시트 누락 | 누락 시트명을 포함해 분석 실패 |
| 무통장 시트 누락 | 정상 분석, 현금 값 0 및 누락 상태 표시 |
| 부가서비스 데이터 행의 강사명 누락 | 실제 행 번호를 포함해 분석 실패 |
| 손상된 엑셀 또는 파서 오류 | 해당 파일명을 포함해 분석 실패 |
| 요약 레이블/숫자 누락 | 계산은 성공, 해당 검증 항목은 불일치 |
| 저장 revision 충돌 | 자동 덮어쓰기 금지, 최신값 복원/강제 저장 선택 제공 |
| PDF 필수 발행 정보 누락 | PDF 요청 전에 차단 |
| PDF 응답이 비어 있거나 PDF가 아님 | 생성 실패 처리 |

## 17. PDF 생성 계약

현재 구현은 서버에서 HTML/CSS를 만든 뒤 Playwright Chromium의 인쇄 기능으로 A4 PDF를 생성한다.

- 요청: `POST /api/pdf/report`
- 종류: `kind = instructor` 또는 `kind = statement`
- 응답 MIME: `application/pdf`
- 응답 헤더: `X-Report-Engine: playwright-chromium`
- 캐시: `no-store`
- 배경색 포함 인쇄
- 한글 글꼴: Pretendard
- 페이지 분할 시 표 행, 요약 카드가 중간에서 잘리지 않게 처리

새 서비스는 PDF 엔진을 바꿀 수 있지만 포함 데이터, 계산값, 파일명, A4 가독성은 동일하게 유지해야 한다.

## 18. 수용 테스트 체크리스트

다음 테스트를 모두 통과하면 계산 이식이 완료된 것으로 본다.

### 입력/파싱

- [ ] 제공된 기존 3개 엑셀을 모두 읽는다.
- [ ] `비즈업_무통장`이 없는 파일을 오류 없이 처리한다.
- [ ] 부가서비스 데이터 행의 빈 강사명을 행 번호와 함께 거부한다.
- [ ] zero-width 문자가 포함된 강사명이 정상 매칭된다.
- [ ] `.xlsx` 이외 파일과 25 MiB 초과 파일을 거부한다.

### 계산

- [ ] 5.4의 반올림 골든 테스트 결과가 정확히 203이다.
- [ ] 취소/부분취소 음수 행을 그대로 합산한다.
- [ ] 시스템노바 수수료를 강사별·월별로 계산 후 합산한다.
- [ ] 현금만 있는 강사의 `settlementAmount`가 시스템 수수료만큼 음수가 될 수 있다.
- [ ] 월이 없는 강사에 0 결과를 삽입한다.
- [ ] `비즈업클래스 정산금`을 `settlementAmount`와 비교한다.

### 정산서

- [ ] 10.4의 모든 골든 값이 정확히 일치한다.
- [ ] 비용이 모두 0이고 A가 100,000이면 사업자 지급액 55,000, 개인 원천징수 1,650, 개인 지급액 48,350, 플랫폼 금액 50,000이다.
- [ ] B는 플랫폼 K에만, E는 강사 I에만 반영된다.
- [ ] 참여 강사 33.3/33.3/33.4% 배분 결과가 33,300/33,300/33,401이다.
- [ ] 붙여넣기의 `총합`/`합계` 행이 중복 합산되지 않는다.

### 통합

- [ ] 파일명이 역순으로 들어와도 월순으로 결과가 정렬된다.
- [ ] 같은 월 또는 월 탐지 실패 시 원래 입력 순서를 유지한다.
- [ ] 분석 결과 저장 후 재시작해도 원본, 결과, 정산서 초안이 복원된다.
- [ ] 파일 추가/삭제 후 작업이 stale이 되고 재분석을 요구한다.
- [ ] 강사 정산표 PDF와 최종 정산서 PDF가 비어 있지 않은 유효 PDF로 생성된다.

## 19. 구현 시 가장 흔한 불일치 원인

1. 합계에 3.3%를 한 번 적용하는 것. 반드시 강사별·월별 적용 후 합산해야 한다.
2. 행 합산 후 한 번 반올림하는 것. 반드시 각 원본 금액 셀을 먼저 반올림한다.
3. 언어 기본 반올림을 사용해 `-20.5`가 `-20`이 되는 것. 기존 결과는 `-21`이다.
4. 취소 행을 상태값으로 제외하는 것. 기존 서비스는 행을 제외하지 않고 음수 금액을 합산한다.
5. 현금 취소액을 무조건 음수로 바꾸는 것. 기존 서비스는 입력 부호를 신뢰한다.
6. 부가서비스 E열을 계산에 쓰는 것. 계산 대상은 F열 총계이다.
7. 요약 시트 열을 고정하는 것. 레이블 오른쪽 첫 숫자를 찾아야 한다.
8. 요약의 비즈업 정산금을 `finalSettlement`와 비교하는 것. `settlementAmount`가 비교 대상이다.
9. 강사명의 쉼표, `x`, 대소문자를 임의로 통합하는 것. 정의된 정규화 외에는 완전 일치이다.
10. 정산서 B를 강사 지급액에서 차감하는 것. B는 플랫폼 몫에서만 차감한다.
