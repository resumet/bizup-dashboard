# 강의별 주문 내역

개별 강의의 **주문 내역** 탭에서 주문결제 목록 엑셀을 가져오고 저장된 주문항목을 검색합니다. 직접 주소는 `/services/course-operations/{courseId}?tab=orders`입니다. 새 강의는 먼저 저장해야 탭이 활성화됩니다.

## DB 적용

기존 강의 운영 DB에 `supabase/migrations/202609120001_course_orders.sql`을 적용합니다. Supabase SQL Editor에서 해당 파일의 SQL 전체를 실행합니다. 주문 내역·가져오기 이력 테이블, 워크스페이스 구성원 조회 정책, 서버 전용 원자적 가져오기 함수를 만듭니다.

적용 후 `npx tsx scripts/verify-course-orders.ts`로 테이블과 필수 열을 읽기 전용으로 확인합니다. `.env.local`의 Supabase 서버 환경변수를 사용하며 실제 개인정보는 출력하지 않습니다.

## 사용 흐름

1. 강의 → **주문 내역** → `.xlsx` 파일 선택 → **파일 분석**.
2. 파일 안의 주문항목명·옵션명·건수를 확인합니다. 강의명을 포함한 상품을 우선 제안하며 예약자용, 신규 등 관련 항목을 직접 선택할 수 있습니다.
3. 선택한 주문항목에서 옵션명을 제외한 가장 짧은 이름을 **저장할 강의명**으로 표시합니다. **선택한 N건 저장**을 누르면 파일을 서버에서 다시 검증한 뒤 선택 항목을 저장하고 해당 이름을 강의명에 반영합니다. 길이가 같으면 가나다순으로 결정합니다.
4. 회원명·휴대전화번호·이메일·결제ID 등으로 검색하거나 주문항목·옵션·상태·결제방법·RS·광고 매체·유입 구분·환불 여부를 필터링합니다. 금액과 환불일은 범위로 검색할 수 있습니다.
5. **수강생 명단 만들기**를 누르면 화면 하단에 결제완료 주문의 이름·전화번호·이메일·옵션명·금액을 표시합니다. 검색·필터·페이지와 관계없이 저장된 전체 주문에서 추출하며 금액은 원본 결제금액입니다. 같은 사람의 서로 다른 주문·옵션은 각각 유지하고 부분환불·취소 등 다른 상태는 제외합니다. 명단은 현재 화면에서 확인하는 용도로, 주문 새로고침 시 갱신되며 페이지를 다시 방문하면 버튼으로 다시 표시합니다.

명단에는 연속 번호와 트래킹 유입 구분도 표시합니다. 010 휴대전화는 `010-0000-0000` 형식으로 표시하며 `+82`, `0082`, 앞자리 0이 빠진 번호도 정규화합니다. 올바르지 않은 번호는 원문을 유지하고 메시지 메뉴를 비활성화합니다.

- 옵션별 필터와 별도로, 전체 명단의 옵션별 인원·결제금액·매출 기여도를 표시합니다. 인원은 정규화한 전화번호, 전화번호가 없거나 잘못된 경우 이메일, 둘 다 없으면 주문별로 구분합니다. 동일인이 여러 옵션을 구매하면 각 옵션에 포함됩니다. 기여도는 옵션 결제금액 ÷ 현재 명단 전체 결제금액 × 100이며, 전체 매출이 0이면 `—`입니다. 필터를 바꿔도 기여도의 기준은 전체 명단으로 유지합니다.
- 오른쪽 점 세 개 메뉴의 **삭제**는 현재 화면의 명단에서만 해당 주문을 제외하며 통계에도 반영합니다. 원본 주문은 유지하며 최근 삭제는 **되돌리기**로 복원합니다. 주문 새로고침 중에도 제외 상태를 유지하고 페이지를 다시 방문하면 복원됩니다.
- **메시지보내기**는 해당 강의의 `강의명 · 주문 수강생 발송` 주소록에 선택한 연락처를 준비하고 기존 알림톡·문자 자동화 화면으로 이동합니다. 강의별 발송용 주소록과 전화번호별 연락처를 재사용하며 한 사람만 선택됩니다. 이름·이메일은 최신 주문 값으로 갱신합니다. 이 단계에서는 메시지를 발송하지 않으며, 발송 화면에서 템플릿·변수를 설정하고 발송합니다. 서버에서 강의 접근 권한과 해당 주문의 결제완료 상태·전화번호를 다시 검증합니다.

저장 항목: 주문항목명 원문, 옵션명, 회원명, 휴대전화번호, 이메일, 결제금액, 환불금액, 현 결제금액, 주문상태, 결제방법, RS, 트래킹 광고 매체, 트래킹 유입 구분, 결제ID, 환불일. 중복 판별에 주문ID도 보관합니다.

- 첫 시트를 읽습니다. `docs/purchase_order_20260912.xlsx`의 열 형식을 지원하며 열 이름의 공백은 무시합니다.
- 옵션은 마지막 공백 포함 ` - ` 구분자의 오른쪽입니다. 공백 포함 구분자가 없다면 마지막 `-` 오른쪽을 사용하며, 구분자가 없으면 옵션 없음으로 표시합니다.
- 주문ID(없으면 결제ID) + 주문항목명 + 강의를 기준으로 중복을 판별합니다. 동일 항목 재업로드는 결제·환불·연락처 등 최신 값으로 갱신하고, 파일에 없는 기존 주문은 유지합니다. 상품명이 바뀌면 다른 주문항목으로 처리됩니다.
- 동일 파일의 완전히 동일한 중복 행은 한 번 저장합니다. 같은 식별자로 서로 다른 내용이 들어오면 오류를 표시합니다. 결제ID와 주문ID가 모두 없거나 금액·날짜가 잘못된 파일은 저장하지 않습니다.
- 결제유형이 `분할결제`이면 같은 주문번호의 행을 먼저 한 결제건으로 통합합니다. 결제금액·환불금액·현 결제금액을 합산하고, 결제ID·결제방법 등 서로 다른 값은 ` / `로 함께 보관합니다. 환불일은 가장 최근 날짜입니다. 같은 결제ID의 완전히 동일한 행은 합산에서 제외하며 상충하는 정보는 오류로 표시합니다. 주문번호가 없으면 분할결제를 저장할 수 없습니다.
- 분할결제의 재업로드 식별자는 강의 + 주문번호입니다. 해당 주문의 모든 분할 내역을 포함한 파일을 다시 올리면 합산한 최신 값으로 갱신합니다. 미리보기 건수도 통합 후 기준입니다.
- 금액 합계는 현재 필터 결과의 주문항목 행 기준이며 인원이나 고유 결제 건수와는 다를 수 있습니다. 현 결제금액은 엑셀 원본 값을 그대로 보관합니다.
- 환불일은 날짜로 보관합니다. 환불금액이 0이 아니거나 환불일이 있으면 환불 있음으로 분류합니다.
- 파일당 최대 4MB, 10,000행이며 표는 페이지당 50건을 표시합니다. 최초 조회는 DB의 1,000행 제한을 넘는 모든 페이지를 불러옵니다.
- 원본 엑셀 파일 자체는 보관하지 않습니다. 선택한 주문 데이터와 파일명·저장 건수·일시·작업자 이력을 DB에 저장합니다.

## 검증

`npx tsx --conditions=react-server --test src/lib/course-orders/*.test.ts`

파싱·필터·업로드 검증·1,000행 이상 조회와 PGlite의 실제 Postgres SQL로 필드 저장, 재업로드 갱신, 강의 격리, 실패 롤백, 조회/실행 권한을 검증합니다. 샘플 파일이 로컬에 있으면 120행이 분할결제 통합 후 115건으로 저장되고 금액 합계가 유지되는지도 확인합니다. 샘플 개인정보 파일은 테스트를 위해 저장소에 추가할 필요가 없습니다.
