# 강의별 주문 내역

개별 강의의 **주문 내역** 탭에서 주문결제 목록 엑셀을 가져오고 저장된 주문항목을 검색합니다. 직접 주소는 `/services/course-operations/{courseId}?tab=orders`입니다. 새 강의는 먼저 저장해야 탭이 활성화됩니다.

## DB 적용

기존 강의 운영 DB에 `supabase/migrations/202609120001_course_orders.sql`을 적용합니다. Supabase SQL Editor에서 해당 파일의 SQL 전체를 실행합니다. 주문 내역·가져오기 이력 테이블, 워크스페이스 구성원 조회 정책, 서버 전용 원자적 가져오기 함수를 만듭니다.

적용 후 `npx tsx scripts/verify-course-orders.ts`로 테이블과 필수 열을 읽기 전용으로 확인합니다. `.env.local`의 Supabase 서버 환경변수를 사용하며 실제 개인정보는 출력하지 않습니다.

## 사용 흐름

1. 강의 → **주문 내역** → `.xlsx` 파일 선택 → **파일 분석**.
2. 파일 안의 주문항목명·옵션명·건수를 확인합니다. 강의명을 포함한 상품을 우선 제안하며 예약자용, 신규 등 관련 항목을 직접 선택할 수 있습니다.
3. **선택한 N건 저장**을 누릅니다. 파일을 서버에서 다시 검증한 뒤 선택 항목만 해당 강의에 저장합니다.
4. 회원명·휴대전화번호·이메일·결제ID 등으로 검색하거나 주문항목·옵션·상태·결제방법·RS·광고 매체·유입 구분·환불 여부를 필터링합니다. 금액과 환불일은 범위로 검색할 수 있습니다.

저장 항목: 주문항목명 원문, 옵션명, 회원명, 휴대전화번호, 이메일, 결제금액, 환불금액, 현 결제금액, 주문상태, 결제방법, RS, 트래킹 광고 매체, 트래킹 유입 구분, 결제ID, 환불일. 중복 판별에 주문ID도 보관합니다.

- 첫 시트를 읽습니다. `docs/purchase_order_20260912.xlsx`의 열 형식을 지원하며 열 이름의 공백은 무시합니다.
- 옵션은 마지막 공백 포함 ` - ` 구분자의 오른쪽입니다. 공백 포함 구분자가 없다면 마지막 `-` 오른쪽을 사용하며, 구분자가 없으면 옵션 없음으로 표시합니다.
- 주문ID(없으면 결제ID) + 주문항목명 + 강의를 기준으로 중복을 판별합니다. 동일 항목 재업로드는 결제·환불·연락처 등 최신 값으로 갱신하고, 파일에 없는 기존 주문은 유지합니다. 상품명이 바뀌면 다른 주문항목으로 처리됩니다.
- 동일 파일의 완전히 동일한 중복 행은 한 번 저장합니다. 같은 식별자로 서로 다른 내용이 들어오면 오류를 표시합니다. 결제ID와 주문ID가 모두 없거나 금액·날짜가 잘못된 파일은 저장하지 않습니다.
- 금액 합계는 현재 필터 결과의 주문항목 행 기준이며 인원이나 고유 결제 건수와는 다를 수 있습니다. 현 결제금액은 엑셀 원본 값을 그대로 보관합니다.
- 환불일은 날짜로 보관합니다. 환불금액이 0이 아니거나 환불일이 있으면 환불 있음으로 분류합니다.
- 파일당 최대 4MB, 10,000행이며 표는 페이지당 50건을 표시합니다. 최초 조회는 DB의 1,000행 제한을 넘는 모든 페이지를 불러옵니다.
- 원본 엑셀 파일 자체는 보관하지 않습니다. 선택한 주문 데이터와 파일명·저장 건수·일시·작업자 이력을 DB에 저장합니다.

## 검증

`npx tsx --conditions=react-server --test src/lib/course-orders/*.test.ts`

파싱·필터·업로드 검증·1,000행 이상 조회와 PGlite의 실제 Postgres SQL로 필드 저장, 재업로드 갱신, 강의 격리, 실패 롤백, 조회/실행 권한을 검증합니다. 샘플 파일이 로컬에 있으면 120행 전체 파싱도 확인합니다. 샘플 개인정보 파일은 테스트를 위해 저장소에 추가할 필요가 없습니다.
