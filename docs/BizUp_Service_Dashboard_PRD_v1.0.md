# 1. 제품 개요

## 1.1 배경

비즈업은 강의별 신청자 엑셀을 반복적으로 정리하고, 신청 현황과 광고 성과를 분석하며, 대상자에게 결제 확인 및 초대 알림톡을 발송해야 한다. 현재 작업은 파일마다 수작업으로 반복되기 쉬워 누락, 중복, 변경 추적 실패, 잘못된 대상 발송 위험이 있다.

## 1.2 제품 비전

비즈업의 여러 내부 서비스를 카드형 플러그인으로 확장할 수 있는 공통 대시보드를 만들고, 첫 번째 플러그인으로 ‘수강생 명단 분석’을 제공한다. 이후 새 서비스는 제목, 설명, 상태, 실행 경로만 등록하면 동일한 대시보드에 카드로 노출된다.

## 1.3 성공 정의

- 운영자가 원본 엑셀을 업로드한 뒤 5분 이내에 컬럼 매핑, 오류 확인, 분석 결과 저장까지 완료한다.

- 동일 작업에 새 엑셀을 반영했을 때 추가·제거·필드 변경이 자동 계산되고 감사 가능한 이력으로 남는다.

- 전체 또는 선택 대상자에게 승인된 알림톡 템플릿을 발송하고, 개인별 성공·실패 내역을 재확인할 수 있다.

- 필요 컬럼, 순서, 출력명, 필터 조건을 지정해 엑셀로 내려받을 수 있다.

# 4. 정보 구조와 화면

## 4.1 공통 서비스 대시보드

- 상단: 비즈업 로고, 서비스 검색, 사용자 메뉴

- 본문: 서비스 카드 그리드. 카드 필드 = 아이콘, 제목, 한 줄 설명, 상태(사용 가능/준비 중), 최근 실행일, ‘실행하기’ 버튼

- 첫 카드: ‘수강생 명단 분석’ — 엑셀 신청자 분류·분석·발송·다운로드

- 새 서비스 등록 구조: service_key, title, description, icon, route, status, display_order, allowed_roles

## 4.2 수강생 명단 분석 화면 흐름

1.  작업 목록: 작업명, 강의명, 최신 인원, 오류 수, 마지막 업데이트, 발송 건수, 상태를 표시한다.

2.  새 작업: 엑셀 업로드 → 시트 선택 → 헤더 행 감지 → 컬럼 자동 매핑/수동 수정 → 검증 → 저장한다.

3.  작업 상세: 요약 KPI, 신청자 표, 분석 탭, 변경 이력 탭, 발송 내역 탭, 파일 버전 탭을 제공한다.

4.  업데이트: 기존 작업에서 새 엑셀을 업로드하고 변경 미리보기 확인 후 적용한다.

5.  내보내기: 필터 적용 → 컬럼 선택/순서 변경/출력명 변경 → 미리보기 → XLSX 다운로드한다.

6.  메시지: 전체/필터 결과/개별 선택 → 템플릿 선택 → 변수 입력·미리보기 → 발송 확인 → 결과 저장한다.

# 5. 기능 요구사항

## 5.1 서비스 플러그인 대시보드

- 서비스 목록은 DB 기반으로 렌더링하되 MVP에서는 관리자만 등록/수정 가능하다.

- status가 active인 서비스만 실행 가능하며 coming_soon은 버튼을 비활성화한다.

- route는 애플리케이션 내부 경로만 허용하고, 역할 권한에 따라 카드 노출을 제어한다.

- 서비스 카드 클릭 및 실행 이벤트를 기록한다.

## 5.2 엑셀 업로드와 컬럼 매핑

- 지원 형식: .xlsx 우선. .xls와 .csv는 후순위 또는 변환 안내. 최대 파일 크기는 초기 20MB로 설정 가능하게 한다.

- 여러 시트가 있으면 사용자가 대상 시트를 선택한다. 첫 행이 헤더가 아닐 경우 헤더 행을 지정할 수 있다.

- 필수 표준 컬럼: 전화번호. 권장 컬럼: 고객명, 이메일, 강의명, 유입경로, 광고매체, 옵션명, 신청일시, 결제상태.

- 한글 컬럼명 변형과 공백을 기반으로 자동 매핑하고, 저장 전 사용자가 확정한다. 매핑 프리셋을 재사용할 수 있다.

- 업로드 원본은 private storage에 저장하고 checksum(SHA-256), 파일명, 크기, 업로더, 업로드 시각을 기록한다.

## 5.3 전화번호 표준화와 오류

- 수강생 식별키는 정규화된 전화번호다. 공백, 하이픈, 괄호, 국가코드(+82)를 제거·변환하여 국내 휴대전화 표준 형식(예: 01012345678)으로 저장한다.

- 전화번호가 없거나 유효성 규칙을 통과하지 못한 행은 오류로 분리하고 작업 완료 전에 오류 목록을 보여준다.

- 오류 행은 정상 신청자 수와 발송 대상에서 제외한다. 원본 행 번호, 오류 사유, 원본 값을 표시하고 오류 엑셀을 내려받을 수 있다.

- 같은 파일에 동일 전화번호가 여러 번 나오면 중복으로 표시한다. 기본값은 최신 신청행 유지이며, 사용자가 병합 규칙을 선택할 수 있다.

| **중요 정책** 전화번호가 없는 행에 임시 ID를 자동 부여하지 않는다. 해당 행은 오류 상태로 보존하고 사용자가 원본을 수정해 다시 업데이트하도록 한다. |
|----------------------------------------------------------------------------------------------------------------------------------------------------|

## 5.4 분류·필터·분석

- 강의명별: 신청자 수, 유효/오류/중복 수, 증감, 결제상태 분포

- 유입경로별: 인원, 비율, 강의별 교차분석

- 광고매체별: 인원, 비율, 유입경로/강의 교차분석

- 옵션명별: 인원, 비율, 결제상태/강의 교차분석

- 필터: 강의명, 유입경로, 광고매체, 옵션명, 결제상태, 신청일 범위, 오류 여부, 발송 여부, 키워드

- 분석 기준의 공백·대소문자·표기 흔들림을 정규화하되 원본 값도 보존한다. 사용자가 그룹 병합 별칭을 설정할 수 있다.

## 5.5 작업 저장과 버전 업데이트

- 작업은 하나의 논리적 데이터셋이며, 최초 업로드와 이후 업데이트 파일은 각각 버전으로 저장한다.

- 새 파일 반영 전 기존 최신 버전과 전화번호 기준으로 비교해 추가, 제거, 변경, 동일, 오류를 계산한다.

- 변경 비교 대상은 모든 매핑 컬럼이며, 전화번호 자체 변경은 동일인을 확정할 보조키가 없으므로 기본적으로 ‘기존 제거 + 신규 추가’로 처리한다.

- 전화번호 변경으로 기록하려면 운영자가 기존 행과 신규 행을 수동 연결하고 사유를 입력해야 한다.

- 업데이트 미리보기에서 건수와 세부 목록을 확인한 뒤 적용 또는 취소한다. 적용은 트랜잭션으로 처리한다.

- 과거 버전은 불변으로 유지하며, 현재 조회는 최신 버전 스냅샷을 사용한다.

## 5.6 변경 이력

| **유형**      | **기록 내용**                                           |
|---------------|---------------------------------------------------------|
| 추가          | 전화번호, 신규 데이터, 원본 행 번호, 버전, 수행자, 시각 |
| 제거          | 전화번호, 이전 데이터, 제거된 버전, 수행자, 시각        |
| 필드 변경     | 전화번호, 필드명, 이전 값, 새 값, 버전, 수행자, 시각    |
| 전화번호 변경 | 이전/새 전화번호, 수동 연결 근거와 사유, 수행자, 시각   |
| 오류 변화     | 오류 생성/해결, 오류 코드, 원본 행 번호                 |

- 변경 이력은 사용자·유형·날짜·전화번호로 검색/필터하며 CSV/XLSX로 내보낼 수 있다.

- 운영자가 임의 수정할 수 없는 감사 로그로 저장하고, 필요한 경우 버전 단위 롤백은 별도 승인 기능으로 후순위 제공한다.

## 5.7 Shoong 알림톡 발송

서버 전용 API Route 또는 Supabase Edge Function에서 Shoong POST /send를 호출한다. 브라우저에서 Shoong API를 직접 호출하지 않으며 API 키와 sender key는 서버 환경변수로 관리한다.

| **업무 템플릿**         | **요청 templatecode**                      | **필수 변수**                    |
|-------------------------|--------------------------------------------|----------------------------------|
| 유료강의 결제 확인 안내 | modified_pay_complete_informat (확인 필요) | 고객명, 강좌명                   |
| 유료강의 결제자 초대    | inivite_paid_kakao_talk (확인 필요)        | 고객명, 강좌명, 입장코드, 링크명 |

| **개발 전 확인 필요** 제공 내용에서 템플릿의 표시 이름과 코드가 서로 교차되어 있다. Shoong 관리자 화면의 실제 templatecode를 기준으로 최종 매핑해야 한다. 또한 ‘inivite’ 철자가 실제 코드인지 확인한다. |
|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|

- 대상 선택: 전체 유효 인원, 현재 필터 결과, 체크한 개별 인원 중 선택한다. 오류 전화번호는 자동 제외한다.

- 템플릿별 변수 입력: 고객명은 행별 자동 매핑, 강좌명은 행 값 또는 공통값 선택, 입장코드/링크명은 공통값 또는 컬럼 매핑을 지원한다.

- 발송 전 예상 대상 수, 제외 수, 템플릿, 변수 샘플 3건을 보여주고 최종 확인을 받는다.

- 대량 발송은 작업 큐로 처리하며 동시성·속도 제한, 지수 백오프, 일시 오류 재시도를 적용한다. 4xx 영구 오류는 자동 재시도하지 않는다.

- 개별 결과에 HTTP 상태, Shoong code, groupId, messageId, 요청 시각, 완료 시각, 실패 사유를 저장한다. Authorization 값과 전체 요청 본문은 로그에 남기지 않는다.

- 중복 발송 방지: send_job별 idempotency_key를 생성하고 동일 대상·템플릿·작업 버전에 대한 재발송 시 경고한다.

## 5.8 맞춤 엑셀 다운로드

- 다운로드 대상은 전체 또는 현재 필터 결과로 선택한다.

- 내보낼 컬럼을 체크박스로 선택하고 드래그앤드롭으로 순서를 바꾸며 출력 컬럼명을 수정한다.

- 전화번호 표시 형식(숫자만/하이픈), 날짜 형식, 빈 값 처리, 파일명과 시트명을 설정한다.

- 상위 20행 미리보기 후 .xlsx로 생성한다. 대용량은 비동기 생성 후 만료되는 다운로드 링크를 제공한다.

- 개인정보가 포함된 다운로드 이벤트를 감사 로그에 남긴다.

# 7. 시스템 아키텍처

- 프론트엔드: Next.js + TypeScript + Tailwind CSS/shadcn 스타일 컴포넌트. Vercel 배포.

- 인증·DB·스토리지: Supabase Auth, Postgres, private Storage, Row Level Security.

- 엑셀 처리: SheetJS 또는 ExcelJS. 작은 파일은 서버 요청 내 처리하고 큰 파일은 비동기 작업으로 전환 가능하게 추상화한다.

- 서버 통합: Next.js Route Handler 또는 Supabase Edge Function. Shoong 키는 서버 비밀값으로만 주입한다.

- 소스/배포: GitHub 브랜치 전략(main/preview), Vercel Preview, production 환경 분리, Supabase migration 버전 관리.

- 장기 작업: MVP 규모에서 Vercel 함수 한도를 넘으면 Supabase Queue/Edge Function 또는 별도 worker를 추가한다.

# 9. 주요 비즈니스 규칙

1. 작업 내 신청자 식별은 정규화 전화번호를 사용한다.

2. 전화번호 누락/형식 오류 행은 저장하되 유효 명단과 발송 대상에서 제외한다.

3. 전화번호가 달라진 두 행은 자동으로 동일인 처리하지 않는다.

4. 버전 업데이트는 미리보기 승인 후에만 최신 상태를 변경한다.

5. 과거 파일 버전과 변경 이벤트는 삭제하지 않고 보존한다. 보존기간 정책에 의한 파기만 예외다.

6. 필터 분석은 최신 적용 버전을 기본으로 하며 사용자가 과거 버전을 조회할 수 있다.

7. 발송은 유효 전화번호이며 필수 템플릿 변수가 모두 채워진 대상만 실행한다.

8. Shoong의 성공 응답만 성공으로 기록하고, 네트워크 단절 상태는 결과 확인 전까지 unknown으로 구분한다.

# 11. 수용 기준

## 11.1 업로드·분석

- 필수 컬럼이 없는 파일은 저장되지 않고 구체적 오류가 표시된다.

- 하이픈/공백/+82 전화번호가 동일한 표준 형식으로 정규화된다.

- 강의명·유입경로·광고매체·옵션명별 인원 합계가 유효 신청자 원장과 일치한다.

- 필터를 조합해도 결과 수와 다운로드 수가 화면 표시와 일치한다.

## 11.2 버전·이력

- 테스트 파일 A에서 B로 업데이트 시 추가/제거/변경 건수가 예상값과 일치한다.

- 각 변경 이벤트에서 이전 값, 새 값, 버전, 사용자, 시각을 조회할 수 있다.

- 업데이트 실패 시 최신 버전과 집계가 변경되지 않는다.

## 11.3 발송

- 전체, 필터 결과, 개별 선택 세 방식의 대상 수가 정확하다.

- 필수 변수가 비어 있는 대상은 발송 전 제외 사유와 함께 표시된다.

- 개인별 성공/실패와 외부 messageId/groupId가 저장되고 재조회된다.

- 브라우저 번들, 네트워크 응답, 앱 로그에 Shoong Authorization 토큰이 노출되지 않는다.

## 11.4 다운로드

- 선택한 컬럼만 지정 순서와 이름으로 생성된다.

- 화면 필터 결과와 엑셀 행 수가 일치하며 한글이 깨지지 않는다.

# 부록 A. Shoong 서버 요청 계약(비밀값 제외)

공통: POST https://api.shoong.kr/send, Content-Type application/json, Authorization Bearer \<SHOONG_API_KEY\>. 구현에서는 점 표기(flat key)를 Shoong 스펙 그대로 전송한다.

| **템플릿** | **payload 키**                                                                                           |
|------------|----------------------------------------------------------------------------------------------------------|
| 결제 확인  | sendType, phone, channelConfig.senderkey, channelConfig.templatecode, variables.고객명, variables.강좌명 |
| 초대       | 위 공통 키 + variables.입장코드, variables.링크명                                                        |

환경변수 예: SHOONG_API_KEY, SHOONG_SENDER_KEY, SHOONG_TEMPLATE_PAID_CONFIRM, SHOONG_TEMPLATE_PAID_INVITE. 값은 GitHub에 커밋하지 않는다.
