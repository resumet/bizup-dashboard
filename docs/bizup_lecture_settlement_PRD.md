# 비즈업클래스 강의별 정산 시스템 PRD

-   문서 버전: v1.0
-   작성일: 2026-08-31
-   제품 유형: 사내 운영용 웹 애플리케이션
-   권장 기술 스택: GitHub + Vercel + Supabase
-   주요 사용자: 정산 담당자, 관리자
-   최종 산출물: 강의별 정산 데이터 + 증빙 자료 + 강사용 PDF 정산서

## 1. 프로젝트 목적

강의별 매출과 비용을 정확하게 검증하고 강사 및 회사의 정산 금액을 자동
계산하는 사내 정산 시스템을 구축한다.

핵심은 단순 계산이 아니라
`노바 원본 → 직접 결제 원본 → 거래별 검증 → 매출 확정 → 비용/증빙 → 정산 계산 → PDF`의
전체 근거를 추적하는 것이다.

## 2. 핵심 업무 흐름

강의 생성 → 노바 월 정산서 업로드 → 직접 결제내역 업로드 → 대상 강의
자동 분류 → 여러 월 데이터 통합 → 노바/직접 결제내역 대조 → 불일치 처리
→ 매출/수수료 확정 → 비용/증빙 등록 → 자동 정산 → 검토/확정 → PDF 생성

## 3. 정산 프로젝트

각 강의를 하나의 Settlement Project로 관리한다.

필드: - 정산 프로젝트 ID - 강의명 - 강사명 - 강의 시작일/종료일 - 정산
대상 월(복수 선택) - 담당자 - 메모 - 상태

상태: - 자료대기 - 자료업로드 - 검증필요 - 검증완료 - 비용입력중 -
정산검토 - 정산확정 - 지급완료

## 4. 노바 정산서

XLSX/XLS/CSV 업로드를 지원한다. 월별 원본 파일을 보존하며 여러 강의가
섞여 있는 데이터를 강의명, 상품명, 옵션명, 상품 ID, 강사명 등의 값으로
자동 분류한다.

표기가 다른 경우 내부 강의와 연결하는 매핑 규칙을 저장하고 이후 업로드에
재사용한다.

하나의 강의가 2개월 이상 진행되면 여러 월의 노바 정산서를 하나의 정산
프로젝트에 연결하고 통합 계산한다. 동시에 월별 원본 및 합계도 확인할 수
있어야 한다.

## 5. 직접 결제내역

회사에서 직접 추출한 결제내역을 업로드한다.

예상 필드: - 주문번호/결제번호 - 결제일 - 결제자명 - 연락처/이메일 -
상품명/옵션명 - 결제금액 - 환불금액 - 실매출 - PG사 수수료 - 노바
수수료 - 결제상태

최초 업로드 시 컬럼 매핑을 제공하고 저장된 매핑을 다음 업로드부터
재사용한다.

## 6. 정산 검증

노바 정산서와 직접 결제내역을 거래 단위 및 합계 단위로 비교한다.

비교 항목: - 결제 건수/결제자 - 주문번호 - 결제금액 - 환불금액 - 전체
매출 - PG 수수료 - 노바 수수료

거래별 상태: - 일치 - 노바에만 존재 - 직접 결제내역에만 존재 - 결제금액
불일치 - 환불금액 불일치 - PG 수수료 불일치 - 노바 수수료 불일치 - 중복
의심 - 확인 필요

합계 화면에는 노바 금액, 직접 추출 금액, 차액, 상태를 나란히 표시한다.
차액이 남으면 정산 확정 전에 경고한다.

불일치 건은
`노바 오류 / 내부 데이터 오류 / 정상 차이 / 확인 완료 / 기타`로 처리하며
사유를 기록한다.

## 7. 결제자 현황

강의별로 다음 정보를 제공한다.

-   결제자 수
-   결제 건수
-   환불 건수
-   총 결제금액
-   총 환불금액
-   전체 매출

상세 테이블: 결제자명 / 결제일 / 상품·옵션 / 최초 결제액 / 환불액 / 최종
매출 / PG 수수료 / 노바 수수료 / 상태

결제자 수와 결제 건수는 별도로 관리한다.

## 8. 매출 계산

정산대상 매출 = 전체 매출 - PG사 수수료 - 노바 수수료

자동 계산 결과뿐 아니라 모든 계산 근거 숫자를 화면에서 확인할 수 있어야
한다.

## 9. 비용 관리

모든 비용은 `회사 부담 / 강사 부담 / 공동 부담` 중 하나를 가진다.

### 회사 부담 기본 항목

1.  유튜브 출연료(고정비)
2.  교안 제작비
3.  상세페이지 제작비
4.  스튜디오 대여비
5.  진행 PD 인건비
6.  광고 집행비
7.  오프라인 행사장 대여비

### 강사 부담 기본 항목

1.  인스타그램 대행비

### 공동 부담 기본 항목

1.  유튜브 출연 RS 비용
2.  광고비

광고비 중복을 방지하기 위해 기본적으로
`광고 운영/대행 관련 비용 = 회사 부담`,
`실제 광고 매체비 = 공동 부담`으로 구분하되 강의별 계약에 따라 변경
가능하게 한다.

공동 부담 기본 비율은 회사 50%, 강사 50%이며 DB에서는 향후 40:60 등의
계약도 지원할 수 있게 비율형으로 저장한다.

사용자는 별도 비용을 추가할 수 있다.

비용 필드: - 비용명 - 부담 주체 - 담당자 - 금액 - 발생일 - 비고 - 증빙
필요 여부 - 증빙 종류 - 첨부파일

## 10. 증빙

기본 증빙 종류: - 세금계산서 - 종이영수증

확장 가능 종류: - 카드영수증 - 계좌이체 내역 - 계약서 - 기타

PDF/JPG/JPEG/PNG를 지원하며 하나의 비용에 여러 증빙을 첨부할 수 있다.

증빙 상태: - 증빙 불필요 - 미등록 - 등록완료 - 확인필요

증빙이 필수인데 미등록된 비용이 있으면 정산 확정 시 경고한다. 관리자가
예외 확정할 경우 사유를 기록한다.

## 11. 정산 계산 엔진

### STEP 1

정산대상 매출 = 전체 매출 - PG 수수료 - 노바 수수료

### STEP 2

분배 기준액 = 정산대상 매출 - 공동 부담 비용

### STEP 3

기본 계약에서는: - 강사 기본분 = 분배 기준액 × 50% - 회사 기본분 = 분배
기준액 × 50%

정산 비율은 강의별 설정값으로 저장한다.

### STEP 4

강사 공급가액 = 강사 기본분 - 강사 부담 비용

### STEP 5

VAT = 강사 공급가액 × 10%

최종 강사 지급분 = 강사 공급가액 + VAT

화면에서 강사 공급가액, VAT, 최종 지급액을 별도로 표시한다.

### STEP 6

회사 지급분 = 회사 기본분 - 회사 부담 비용

## 12. 정산 결과 화면

상단: - 강의명 - 강사명 - 강의기간 - 정산기간 - 담당자 - 상태

매출: - 결제자 수/결제 건수/환불 건수 - 총 결제액/총 환불액/전체 매출

수수료: - PG 수수료 - 노바 수수료 - 총 수수료 - 정산대상 매출

비용은 회사 부담/공동 부담/강사 부담 카드로 구분하고 각각 합계와
상세내역을 표시한다.

최종 정산 영역에는 정산대상 매출 → 공동비용 → 분배 기준액 → 강사/회사
기본분 → 개별 부담비용 → 강사 공급가액/VAT/최종 강사 지급액 → 회사
지급분의 계산 흐름을 보여준다.

## 13. PDF 정산서

정산 확정 후 강사 전달용 PDF를 생성한다.

### 1페이지: 정산 요약

회사명, 강사명, 강의명, 강의기간, 정산기간, 정산일, 결제자 수, 전체
매출, PG/노바 수수료, 정산대상 매출, 공동비용, 강사 기본분, 강사
부담비용, 공급가액, VAT, 최종 강사 지급액을 표시한다.

최종 강사 지급액을 가장 강조한다.

### 2페이지: 매출/수수료 상세

월별 정산, 결제자 수, 결제액, 환불액, 매출, PG 수수료, 노바 수수료.

### 3페이지: 비용 상세

회사/강사/공동 부담별 비용명, 금액, 담당자, 비고, 증빙 여부.

### 이후 페이지: 증빙

이미지는 페이지에 삽입하고 PDF 증빙은 원본 페이지를 정산서 뒤에
병합한다. 증빙 앞에 비용명, 금액, 부담주체, 증빙종류 식별 헤더를 둔다.

PDF 출력 옵션: - 결제자 상세 포함/제외 - 회사 부담 상세 포함/제외 - 내부
비고 포함/제외 - 증빙 포함/제외

강사용 기본 PDF에는 내부 전용 메모를 제외한다.

## 14. 변경 이력 및 버전

매출, 결제자, 환불, 수수료, 비용, 부담주체, 증빙, 정산비율, 확정/재오픈
등의 변경을 모두 기록한다.

기록: - 수정일시 - 수정자 - 항목 - 변경 전 - 변경 후 - 수정 사유

정산 확정 후 기본적으로 수정 불가.
`정산 재오픈 → 사유 입력 → 수정 → 재확정` 절차를 사용한다.

기존 확정본은 삭제하지 않고 Settlement Version으로 보존한다.

Supabase Storage 예시:

settlements/{settlement_id}/expenses/

## 18. 데이터 안전장치

금액은 부동소수점으로 계산하지 않는다. 원 단위 정수 또는 DB
Numeric/Decimal을 사용한다.

계산 결과에는 당시 사용된 원본값과 계산식, 버전을 함께 저장한다. 과거
확정 PDF를 재생성해도 당시 값이 바뀌어서는 안 된다.

동일 파일/거래 중복은 파일 Hash, 주문번호, 거래번호, 결제일+결제자+금액
등의 조합으로 탐지한다.

다월 데이터 통합 - 강의별 자동 분류 - 거래/합계 대조 - 불일치 처리 -
매출/수수료 계산 - 비용 및 부담주체 관리 - 사용자 추가 비용 - 증빙
첨부 - 정산 계산 - 확정/재오픈 - PDF 생성 및 증빙 병합 - 변경 이력/버전
관리

Phase 2: - 강사별 계약 정산비율 - 정산 템플릿 - 이전 비용 복사 - 반복

## 22. 완료 조건

MVP는 다음 흐름이 완전히 동작하면 완료다.

강의 생성 → 2개월 이상의 노바 정산자료 연결 → 직접 결제내역 업로드 →
강의별 거래 분류 → 자동 대조 → 누락/차액/환불/수수료 오류 처리 → 검증
확정 → 회사/강사/공동 비용 입력 → 증빙 첨부 → 자동 정산 → 담당자 검토 →
정산 확정 → 증빙이 포함된 강사용 PDF 생성 → 이후 수정 시 기존 확정본
보존 및 새 버전 생성.

## 23. 핵심 성공 기준

담당자가 강의 하나를 열었을 때 즉시 다음을 확인할 수 있어야 한다.

-   실제 매출은 얼마인가?
-   노바 정산서는 정확한가?
-   PG 및 노바 수수료는 얼마인가?
-   어떤 비용이 발생했는가?
-   각 비용은 누가 부담하는가?
