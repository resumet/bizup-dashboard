# 주문내역 명단의 취소·환불 제외 승인

주문내역의 `수강생 명단 만들기` 미리보기에서 신규·변경 외에 제외 후보를 표시한다. 결제완료 주문이 0건이어도 비교할 수 있다.

- 연결 주문이 취소/환불 상태이고 잔여 결제금액이 0원이거나, 연결 주문이 최신 주문내역에서 사라진 경우 제외 후보로 표시한다.
- 주문 누락은 취소·환불이 확정된 것이 아니므로 사유를 표시하고 운영자가 확인한다.
- 부분환불(잔액 있음), 수동 등록, 주문 연결이 없는 수강생, 이미 환불 처리된 명단은 제외 후보에 넣지 않는다.
- 재결제는 기존 명단 갱신을 우선하며, 모호한 연결은 보류한다.
- 제외 후보는 기본 체크하지 않는다. 신규·변경 전체 선택에서도 제외한다. 개별 체크 후 `승인·반영`을 눌러야 적용된다.
- 승인한 수강생은 현재 명단에서 빠지고 기존 환불자 목록에 남는다. 연락처·메모·카톡방 참여·연결 수강생 등 기존 정보를 유지한다.
- 미리보기 후 주문이나 명단이 변경되면 적용을 거절한다. 신규·변경·제외를 한 트랜잭션으로 처리하여 일부만 적용되지 않는다.

## 운영 반영 순서

1. Supabase SQL Editor에서 `supabase/migrations/202609180001_paid_roster_removal_review.sql` 전체를 실행한다. 기존 `paid_roster_snapshot` 및 `apply_paid_roster_changes` 함수가 있는 DB를 대상으로 한다.
2. 앱 변경을 배포한다. 새 함수가 없는 상태에서는 제외 적용 시 DB 업데이트 필요 오류를 표시하며 기존 명단을 변경하지 않는다.

SQL은 승인 적용용 함수를 추가하며, 실행 자체로 수강생 데이터를 변경하지 않는다. 새 함수는 서버 service role만 실행할 수 있고 내부에서 워크스페이스 권한을 확인한다.
