# 주소록 수강 강의 조회와 결제정보 갱신

주소록 상세의 이름을 클릭하면 저장된 유료수강생 명단에서 해당 연락처가 포함된 강의명·기수·강사명을 표시한다. 강의명을 누르면 해당 강의의 유료수강생 탭으로 이동한다.

- 이름이 아닌 정규화된 전화번호로 비교한다. 대신 수강자가 등록된 행은 실제 수강생 번호로 비교하고 환불자는 제외한다.
- 요청한 주소록의 워크스페이스 멤버십과 연락처 소속을 검증한 뒤 같은 워크스페이스의 강의에 연결된 유료 명단만 조회한다.
- 각 명단의 최신 버전만 1,000건씩 읽으며 최대 4개 명단을 동시에 조회한다. 같은 강의는 한 번만 표시한다.
- 응답에는 강의 ID·이름·기수·강사명만 포함한다. 조회 실패는 빈 결과로 처리하지 않으며 재시도를 제공한다. 팝업을 닫으면 요청을 취소한다.

결제자에서 유료수강생 명단을 만들 때 주문항목명·옵션명·결제금액을 비교한다. 변경 미리보기에는 이전 값과 새 값을 표시하며 신규·변경은 기본 선택된다. 승인 후 추가·갱신·제외 건수를 안내한다.

주문항목명이 주문 키에 포함되어 있으므로 항목명 변경으로 키가 바뀌어도 유일한 주문번호 또는 결제ID로 기존 행을 연결한다. 복수 후보는 자동 연결하거나 제거하지 않고 확인 필요로 남긴다. 같은 사람의 별도 구매를 이름·전화번호만으로 합치지 않는다. 엑셀 갱신의 기존 자동 동기화에도 이 비교 규칙이 적용된다.

마이그레이션 `20261014132913_track_paid_roster_payment_items.sql`은 기존 저장 함수에 주문항목명과 원본 주문번호·결제ID 추적 필드를 추가한다. 기존 행은 다음 갱신 시 채워지며 미리보기에 이전 주문항목이 없으면 `기록 없음`으로 표시한다. 수강생 정보·비고·단톡방 상태와 기존 버전은 보존한다. 스냅샷 동시 수정 검사, 트랜잭션 및 서비스 역할 전용 실행 권한을 유지한다.

검증:

- `src/lib/address-books/contact-courses.test.ts`: 번호 정규화, 동명이인, 환불, 대신 수강자.
- `src/lib/course-orders/reconcile-roster.test.ts`: 항목·옵션·금액 개별 변경, 키 변경·모호한 거래, PGlite에서 실제 SQL 적용 및 정보·이력 보존, 동시 수정·권한 검사.
- `scripts/verify-contact-courses.cjs`: 실제 API의 권한·주소록 소속·최신 버전·1,000건 초과 조회, 결제 변경 미리보기 무쓰기·stale 승인 거부·반영 건수. 실제 주소록 컴포넌트의 이름 클릭·강의 이동·빈 결과·오류·재시도·요청 취소 및 PC·모바일 화면.
- 운영 보안 자문은 기존 기준과 비교한다. 이번 변경으로 추가된 자문은 없어야 하며 기존 항목은 `docs/protected-address-book.md`에 기록되어 있다.
