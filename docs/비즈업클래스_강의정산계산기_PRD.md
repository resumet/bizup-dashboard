# 비즈업클래스 강의 정산 계산기 PRD

- 문서 버전: 1.0 — 최신 확정 계산 방식 기준
- 목적: 현재 계산기의 기능을 Codex에서 동일하게 구현하기 위한 독립적인 개발 명세
- 서비스명: 비즈업클래스 · 강의 정산 계산기
- 참고 화면: [현재 정산 계산기](https://bizup-settlement.kwon-jung-in-2151.chatgpt.site)
- 모든 금액의 내부 계산 단위: 원(KRW)

## 1. 제품 목표

강의 평균 가격, 판매 수량, 비용을 입력하면 전체 매출부터 회사·강사의 최종 정산금까지 한 화면에서 확인하는 웹 계산기를 만든다. 판매 수량 슬라이더를 움직이거나 금액을 수정하는 즉시 전체 결과를 갱신한다.

최신 확정 규칙은 다음과 같다.

1. 전체 매출에서 **PG사 수수료 7.5%**를 먼저 차감한다.
2. **PG 수수료를 차감하고 남은 금액의 3.3%**를 노바 수수료로 차감한다.
3. 정산대상 매출에서 공동부담 광고비와 RS 비용을 전액 차감한다.
4. 남은 금액을 회사와 강사에 각각 50%씩 배분한다.
5. 회사분에서는 회사부담 고정비를 차감한다. 광고 집행비는 **광고비의 16.5%**다.
6. 강사분에는 강사 정산대상금액의 부가세 10%를 더한다.
7. **최종 회사분 ÷ 전체 매출 × 100**으로 회사 순이익률을 표시한다.

## 2. 구현 범위

| 구분 | 요구사항 |
| --- | --- |
| 화면 | 단일 페이지 계산기 |

| 계산 | 브라우저에서 즉시 실행 |
| 결과 | 전체 매출, 수수료, 비용, 배분 내역, 최종 정산금, 회사 순이익률 |
| 저장 | 저장 기능 없음. 상태는 현재 페이지 메모리에서만 유지 |
| 새로고침 | 모든 입력을 기본값으로 초기화 |

이 버전에는 데이터베이스, 백엔드 API, 회원가입·로그인, 관리자 페이지, 결제 연동, 계산 이력, 엑셀 내보내기를 추가하지 않는다. localStorage, sessionStorage, IndexedDB, 쿠키에 입력값을 저장하지 않는다. 금액을 바꾸기 위해 별도의 ‘계산’ 버튼을 누를 필요가 없어야 한다.

## 3. 입력값과 고정 비율

### 3.1 사용자 입력값

금액 입력은 쉼표를 표시하되 내부 상태에는 숫자를 저장한다. 금액은 모두 0원 이상, 1,000,000,000,000원 이하의 정수다.

| 영역 | 입력 항목 | 상태 키 | 기본값 | UI / 제한 |
| --- | --- | --- | ---: | --- |
| 매출 설정 | 강의 평균 가격 | `price` | 2,000,000원 | 금액 직접 입력 |
| 매출 설정 | 판매 수량 | `quantity` | 50개 | 0~100개 슬라이더, 1개 단위 |
| 강사·회사 공동부담 | 광고비 | `ad` | 30,000,000원 | 금액 직접 입력 |
| 강사·회사 공동부담 | RS 비용 | `rs` | 10,000,000원 | 금액 직접 입력. 비율이 아닌 비용 금액 |
| 회사부담 고정비 | 교안 / 상세페이지 | `materials` | 1,500,000원 | 금액 직접 입력 |
| 회사부담 고정비 | 유튜브 출연료 | `youtube` | 3,000,000원 | 금액 직접 입력 |
| 회사부담 고정비 | 행사장 대여비 | `venue` | 2,000,000원 | 금액 직접 입력 |

평균 가격 200만 원과 판매 수량 50개는 최초 화면의 예시 기본값이며, 사용자가 수정할 수 있다. 비용 기본값은 위 표를 사용한다.

### 3.2 자동 계산하는 비율

| 항목 | 비율 | 적용 기준 | 직접 수정 |
| --- | ---: | --- | --- |
| PG사 수수료 | 7.5% | 전체 매출 | 불가 |
| 노바 수수료 | 3.3% | PG사 수수료 차감 후 금액 | 불가 |
| 광고 집행비 | 16.5% | 공동부담 광고비 입력값 | 불가 |
| 회사 배분 | 50% | 공동부담 비용 차감 후 남은 금액 | 불가 |
| 강사 배분 | 50% | 공동부담 비용 차감 후 남은 금액 | 불가 |
| 강사 부가세 | 10% | 강사 정산대상금액 | 불가 |

집행비는 회사부담 고정비 영역에 ‘광고비의 16.5% · 자동 계산’으로 표시한다. 광고비를 변경하면 집행비도 즉시 변경한다. 16.5%로 계산한 집행비에 부가세를 추가로 더하지 않는다.

## 4. 계산 명세

계산은 아래 순서를 그대로 따른다. `fee`는 노바 수수료를 뜻하며, `half`는 회사와 강사의 동일한 배분 전용 금액이다.

| 순서 | 계산 결과 | 결과 키 | 계산식 |
| --- | --- | --- | --- |
| 1 | 전체 매출 | `gross` | `price × quantity` |
| 2 | PG사 수수료 | `pg` | `gross × 0.075` |
| 3 | PG 차감 후 금액 | `afterPg` | `gross − pg` |
| 4 | 노바 수수료 | `fee` | `afterPg × 0.033` |
| 5 | 정산대상 매출 | `settlement` | `afterPg − fee` |
| 6 | 공동부담 비용 합계 | `shared` | `ad + rs` |
| 7 | 공동비용 차감 후 남은 금액 | `remaining` | `settlement − shared` |
| 8 | 회사 정산대상금액 | `half` | `remaining × 0.5` |
| 9 | 강사 정산대상금액 | `half` | `remaining × 0.5` |
| 10 | 광고 집행비 | `execution` | `ad × 0.165` |
| 11 | 회사부담 고정비 합계 | `companyCosts` | `execution + materials + youtube + venue` |
| 12 | 최종 회사분 | `companyFinal` | `half − companyCosts` |
| 13 | 회사 순이익률(%) | `companyMargin` | `gross > 0`이면 `companyFinal ÷ gross × 100`, 아니면 `null` |
| 14 | 강사 부가세 | `vat` | `half × 0.1` |
| 15 | 부가세 포함 최종 강사분 | `instructorFinal` | `half + vat` |

정산대상 매출의 교차 확인식은 `gross × 0.925 × 0.967`, 즉 `gross × 0.894475`다. 화면에서는 PG와 노바의 각 차감 금액과 중간 잔액을 개별적으로 보여준다.

### 4.1 비용 적용 원칙

- 광고비와 RS 비용은 회사·강사 배분 **전에 전액** 차감한다. 각각 반만 차감한 뒤 다시 나누지 않는다.
- 집행비, 교안 / 상세페이지, 유튜브 출연료, 행사장 대여비는 회사·강사 배분 **후 회사분에서만** 차감한다.
- 노바 수수료는 `gross × 0.033`으로 계산하지 않는다. 반드시 `afterPg × 0.033`을 사용한다.
- 강사 부가세는 강사 정산대상금액에만 10%를 가산한다. 이를 회사분에서 추가 차감하지 않는다.
- 입력 비용에 별도의 부가세나 원천세 계산을 임의로 추가하지 않는다.
- 회사 순이익률의 분모는 수수료 차감 전 **전체 매출**이다.

## 5. 화면 명세

### 5.1 전체 구성

- 상단에 `bizupclass 비즈업클래스`, 서비스명 `강의 정산 계산기`를 표시한다.
- 설명: `가격과 판매 수량을 바꾸며 예상 정산금을 확인하세요.`
- 배분 비율 표시: `강사 50% / 회사 50%`.
- 데스크톱에서는 왼쪽에 입력 영역, 오른쪽에 정산 결과를 배치한다.
- 모바일에서는 매출 설정 → 정산 결과 → 공동부담 비용 → 회사부담 비용 순서로 배치한다.
- 첫 화면에서 평균 가격, 판매 수량 슬라이더, 주요 결과를 바로 확인할 수 있게 한다.

### 5.2 매출 설정

- 평균 가격 입력 필드, 판매 수량 슬라이더, 현재 선택한 수량, 전체 매출을 표시한다.
- 슬라이더의 범위는 0~100, 간격은 1, 기본값은 50이다.
- 슬라이더 아래 눈금은 `0개 / 25 / 50 / 75 / 100개`로 표시한다.
- 현재 선택한 수량은 `50개`처럼 크게 표시한다.
- 마우스로 드래그하는 동안과 터치로 움직이는 동안 계속 재계산한다. 드래그 종료 시점까지 계산을 미루지 않는다.

### 5.3 강사·회사 공동부담 비용

- 제목: `강사·회사 공동부담`.
- 설명: `배분 전 정산대상 매출에서 전액 차감`.
- 광고비와 RS 비용을 입력하고, 아래에 공동부담 합계를 표시한다.

### 5.4 회사부담 고정비

- 제목: `회사부담 고정비`.
- 설명: `배분 후 회사 정산대상금액에서 차감`.
- 자동 계산한 집행비와 직접 입력하는 세 가지 비용을 표시한다.
- 아래에 회사부담 합계를 표시한다.

### 5.5 최종 결과 카드

| 카드 | 필수 표시 항목 |
| --- | --- |
| 최종 회사분 | `companyFinal`, 매출 대비 회사 순이익률 `companyMargin`, 회사부담 고정비 합계 |
| 최종 강사분 | `instructorFinal`, ‘부가세 포함’ 배지, 부가세 포함 전 금액 `half` |

회사 카드에는 `회사 정산대상금액 − 회사부담 고정비`, 강사 카드에는 `강사 정산대상금액 + 부가세 10%`를 설명으로 표시한다. 회사 순이익률은 회사 최종금액 바로 아래에서 쉽게 찾을 수 있어야 한다.

### 5.6 정산 계산 내역

다음 항목을 순서대로 표시한다.

1. 전체 매출 및 `평균 가격 × 판매 수량`.
2. PG사 수수료 7.5% 차감액.
3. PG 수수료 차감 후 금액.
4. 노바 수수료 3.3% 차감액. 보조 문구: `PG 수수료 차감 후 금액 기준`.
5. 정산대상 매출.
6. 공동부담 광고비 차감액.
7. 공동부담 RS 비용 차감액.
8. 공동비용 차감 후 남은 금액.
9. `남은 금액을 절반씩 배분` 안내.
10. 회사 50%: 정산대상금액 → 회사부담 고정비 차감 → 최종 회사분.
11. 강사 50%: 정산대상금액 → 부가세 10% 가산 → 최종 강사분.

차감 항목은 음수 기호, 가산 항목은 양수 기호로 표현한다. 실제 계산 결과가 음수인 경우에는 실제 부호를 표시한다.

### 5.7 화면 안내 문구

- `전체 매출에서 PG사 수수료 7.5%를 먼저 차감한 뒤, 남은 금액의 3.3%를 노바 수수료로 차감합니다.`
- `회사 순이익률 = 최종 회사분 ÷ 전체 매출 × 100. 소수점 둘째 자리까지 표시합니다.`
- `강사 부가세는 강사 정산대상금액의 10%이며, 회사분에서 추가 차감하지 않습니다.`
- `중간 계산은 반올림하지 않고, 표시 금액만 원 단위로 반올림합니다.`
- 하단: `입력값은 저장되지 않습니다. 새로고침하면 기본값으로 돌아갑니다.`

## 6. 입력·표시·예외 처리

### 6.1 입력 검증

- 금액은 정수만 허용한다. 음수, 소수, 문자, 무한대, 숫자가 아닌 값은 계산에 반영하지 않는다.
- `3,000,000`처럼 쉼표가 있는 값을 붙여 넣을 수 있어야 한다.
- 입력한 숫자는 천 단위 쉼표를 표시한다. 입력 중 커서 위치를 가능한 한 유지한다.
- 금액 입력란을 완전히 비운 동안은 0으로 계산한다. 포커스를 벗어나면 `0`을 표시한다.
- 잘못된 값을 입력하면 해당 필드에 오류를 표시하고, 그 필드의 마지막 유효값으로 계산한다.
- 다른 정상 필드와 슬라이더는 오류가 있는 동안에도 계속 동작한다.
- 판매 수량은 항상 0~100의 정수다.

오류 메시지 예시:

- `0 이상의 정수를 입력해 주세요. 현재 결과는 마지막 유효값 기준입니다.`
- `1조 원 이하로 입력해 주세요. 현재 결과는 마지막 유효값 기준입니다.`

### 6.2 금액 및 비율 표시

- 모든 금액에 천 단위 쉼표와 `원`을 표시한다.
- 원 단위 반올림은 표시 시점에만 한다. 중간 계산이나 저장된 계산 결과에는 반올림한 값을 다시 사용하지 않는다.
- 음수 금액도 절댓값을 반올림한 뒤 원래 부호를 붙인다. 예: `−1.5원`의 표시는 `−2원`.
- 표시 결과가 0원이면 음수 기호를 붙이지 않는다.
- 회사 순이익률은 소수점 둘째 자리까지 표시한다. 예: `13.27%`, `29.00%`, `-6.68%`.
- 표시 금액의 합이 반올림 때문에 1원 정도 달라질 수 있으므로, 계산 검증은 반올림 전 결과를 기준으로 한다.

### 6.3 매출이 0원인 경우

- 평균 가격이 0원이거나 수량이 0개이면 전체 매출과 두 수수료는 0원이다.
- 입력된 광고비, RS 비용, 회사부담 고정비는 그대로 적용한다.
- 회사 순이익률의 내부 값은 `null`로 두고 화면에는 `계산 불가`를 표시한다.
- 설명: `전체 매출이 0원이므로 비율을 계산할 수 없습니다.`
- `NaN`, `Infinity`, 임의의 `0.00%`를 표시하지 않는다.

### 6.4 적자 처리

- 공동비용 차감 후 남은 금액, 회사분, 강사분이 음수여도 0으로 보정하지 않는다.
- 남은 금액이 음수일 때도 50:50으로 배분한다.
- 강사 정산대상금액이 음수이면 부가세 가산액도 음수로 계산한다. 현재 계산기의 산식을 그대로 재현한다.
- 최종 회사분이 음수이면 회사 카드에 `손실`을 표시한다.
- 공동비용 차감 후 적자 안내: `공동비용 차감 후 적자입니다. 요청한 계산식에 따라 음수 금액도 50:50으로 배분하며, 강사분의 부가세 10%도 음수로 반영됩니다.`
- 공동비용 차감 후에는 양수이나 최종 회사분만 음수인 경우: `회사부담 고정비를 차감하면 회사분에 손실이 발생합니다.`

## 8. 기술 구현 가이드

새 프로젝트라면 HTML, CSS, JavaScript 모듈로 구성한 정적 웹앱이면 충분하다. 기존 프로젝트가 있다면 그 기술 구성을 유지하면서 같은 기능을 구현한다. 특정 호스팅 서비스나 외부 API에 의존하지 않도록 한다.

| 파일 / 모듈 | 책임 |
| --- | --- |
| `index.html` 또는 단일 페이지 컴포넌트 | 한국어 화면, 입력 필드, 결과 카드, 정산 내역, 메타데이터 |
| `styles.css` 또는 기존 스타일 파일 | 반응형 배치, 입력·슬라이더 상태, 숫자 표시, 포커스 |
| `calculator.js` 또는 동등 모듈 | 입력 검증과 순수 계산 함수 |
| `app.js` 또는 상태 관리 컴포넌트 | 메모리 상태, 입력 처리, 계산 결과 렌더링 |

- 계산 함수는 DOM 조작, 저장, 네트워크 요청을 포함하지 않는 순수 함수로 분리한다.
- 모든 출력은 동일한 입력 상태와 동일한 계산 함수의 반환값에서 파생한다.
- 입력 이벤트에서 상태를 갱신하고 즉시 전체 결과를 렌더링한다. 슬라이더는 `input` 이벤트 또는 동등한 연속 변경 이벤트를 사용한다.
- 키보드로 입력 필드와 슬라이더를 사용할 수 있어야 한다. 각 필드에 접근 가능한 라벨을 연결한다.
- 슬라이더의 현재 값을 보조 기술에서도 `50개`처럼 읽을 수 있게 한다.
- 결과 요약은 `aria-live="polite"` 또는 동등 방식으로 안내한다. 드래그 중 과도한 안내를 줄이는 지연은 약 350ms로 설정할 수 있지만, 시각적 계산은 즉시 반영한다.
- 미지원 브라우저용 부가 기능이 없어도 일반 계산기는 정상 작동해야 한다.
- 한국어 페이지 제목과 계산기 모양의 간단한 파비콘을 포함한다.

### 8.1 기존 부가 기능: 지원 환경의 에이전트 인터페이스

현재 구현에는 브라우저가 `document.modelContext.registerTool`을 지원할 때만 등록하는 부가 도구가 있다. 동일 환경에서 이를 재현할 경우 아래 동작을 유지한다. 미지원 환경에서는 등록을 건너뛰고 계산기를 정상 제공한다.

| 도구 이름 | 동작 |
| --- | --- |
| `configure_settlement` | 7개 입력 키 중 하나 이상을 한 번에 변경하고 화면을 갱신한다. 알 수 없는 키와 유효하지 않은 값은 반영 전에 거부한다. |
| `read_settlement` | 현재 입력값과 반올림 전 계산 결과를 반환한다. 상태를 바꾸지 않는다. |

반환 형태는 `{ inputs, results, currency: "KRW" }`다. 별도의 서버를 추가하지 않으며, 도구도 화면과 같은 상태·검증·계산 함수를 사용한다. 이 부가 기능의 지원 여부가 일반 사용자 계산 기능을 막아서는 안 된다.

## 부록 A. 기준 계산 함수

다음은 현재 계산기의 계산 모듈이다. 이 함수 또는 동등한 결과를 내는 구현을 사용한다. `fee`는 노바 수수료이며, 회사 순이익률은 퍼센트 값으로 반환한다.

```javascript
export const DEFAULTS = Object.freeze({price: 2000000, quantity: 50, ad: 30000000, rs: 10000000, materials: 1500000, youtube: 3000000, venue: 2000000});
export const MONEY_KEYS = Object.freeze(['price', 'ad', 'rs', 'materials', 'youtube', 'venue']);
export const MAX_MONEY = 1000000000000;

export function validateValues(values) {
  for (const key of MONEY_KEYS) {
    if (!Number.isSafeInteger(values[key]) || values[key] < 0 || values[key] > MAX_MONEY) throw new RangeError(`${key}: 0~${MAX_MONEY} 사이의 정수 금액을 입력해 주세요.`);
  }
  if (!Number.isInteger(values.quantity) || values.quantity < 0 || values.quantity > 100) throw new RangeError('판매 수량은 0~100 사이의 정수여야 합니다.');
  return values;
}

export function calculate(values) {
  validateValues(values);
  const {price, quantity, ad, rs, materials, youtube, venue} = values;
  const gross = price * quantity;
  const pg = gross * 75 / 1000;
  const afterPg = gross - pg;
  const fee = afterPg * 33 / 1000;
  const settlement = afterPg - fee;
  const shared = ad + rs;
  const remaining = settlement - shared;
  const half = remaining / 2;
  const execution = ad * 165 / 1000;
  const companyCosts = execution + materials + youtube + venue;
  const companyFinal = half - companyCosts;
  const companyMargin = gross > 0 ? companyFinal / gross * 100 : null;
  const vat = half / 10;
  const instructorFinal = half + vat;
  return {gross, pg, afterPg, fee, settlement, ad, rs, shared, remaining, half, execution, companyCosts, companyFinal, companyMargin, vat, instructorFinal};
}
```
