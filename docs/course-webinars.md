# 라이브 웨비나 실적

강의 운영 상세의 **라이브 웨비나** 탭에서 최종 단톡방·소통방·라이브 시작/최대/종료 인원, 최대 도달 시간, 광고비, 결제 건수, 총 매출을 입력하고 `웨비나 정보 저장`을 누른다. 최대 도달 시간은 시작부터 경과한 시간으로 1시간 30분은 `1.5`다. 인원·결제·금액은 0 이상의 정수, 시간은 소수 둘째 자리까지 받는다. 빈칸은 미입력으로 보존하며 0과 구분한다. 주문/정산/비용 업로드와 별도로 입력하는 최종 실적이다.

WORK 메인의 **라이브 웨비나 대시보드** 서비스 카드를 누르면 전용 화면 `/services/course-webinars`로 이동한다. 전용 화면에서 접근 가능한 모든 강의를 미입력 강의까지 조회한다. 강의·강사명 검색과 서울 시간 기준 개최 월 필터를 제공하며, 강의명을 누르면 해당 강의의 입력 탭으로 이동한다. 표는 20개씩 표시하고 집계는 현재 검색/월 조건의 전체 결과를 사용한다. API는 DB 응답 개수 제한을 넘는 강의도 끝까지 조회한다.

계산 기준:

- 단톡방 → 라이브 시작 = 라이브 시작 인원 / 최종 단톡방 인원 × 100
- 라이브 최대 → 결제 = 결제 건수 / 라이브 최대 인원 × 100
- 단톡방 → 결제 = 결제 건수 / 최종 단톡방 인원 × 100
- ROAS = 총 매출 / 광고비 × 100 (이익률과 다름)

분모 0 또는 미입력은 `—`다. 소통방 인원은 단톡방 인원에 더하지 않는다. 구매 전환율은 결제 건수 기준으로, 고유 구매자 수나 라이브 참석자별 실제 구매 추적 결과가 아니다. 라이브 → 결제는 최대 인원을 분모로 사용하며, 최대 인원이 미입력이면 시작 인원으로 대체하지 않는다. 전체 비율은 두 값이 모두 입력된 동일 강의 집합에서 분자·분모를 각각 합산하며 집계 대상 강의 수를 표시한다. 광고비·매출 합계 카드는 각 항목에 입력된 값을 합산하므로 부분 입력이 있으면 ROAS 계산 대상과 다를 수 있다.

## 운영 적용

기존 DB에 `supabase/migrations/202609150001_course_webinar_metrics.sql` 전체를 SQL Editor의 `postgres` 역할 또는 기존 마이그레이션 배포 절차로 적용한 뒤 앱을 배포한다. 별도 환경변수는 없다. 기존 강의·워크스페이스 테이블과 `is_workspace_member` 함수를 사용하며 입력 전의 강의 행은 만들지 않는다.

저장용 테이블은 강의당 한 행이며 강의 삭제 시 함께 제거된다. 세션 인증과 워크스페이스 권한을 확인하고, 조회는 RLS로 제한하며 저장은 검증하는 RPC만 허용한다. 이전 저장 버전과 다르면 409로 거절한다. 충돌 시 입력값은 화면에 유지되고 `새로 불러오기`로 최신 데이터를 가져올 수 있다. DB 적용 전에는 로딩 오류와 재시도 버튼을 표시하고 WORK의 다른 도구는 사용할 수 있다.

## 검증

`npx tsx --conditions=react-server --test src/lib/course-webinars/*.test.ts`로 계산/입력 검증과 격리 PostgreSQL의 저장·재시작·권한·충돌을 확인한다. `node scripts/verify-webinars.cjs`는 실제 입력/대시보드 컴포넌트를 로컬 브라우저에서 검증한다. 운영 계정이나 실데이터를 변경하지 않는다.
